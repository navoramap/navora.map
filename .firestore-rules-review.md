# Firestore Rules Review

## Access Inventory

- `users/{uid}` and nested account collections: profile, saved routes and addresses, driving/route history, SOS data, point ledger, and AI chats. Access is UID-scoped.
- `road_reports`: authenticated reads; creation is limited to the signed-in reporter; reports expire within 24 hours. Each other signed-in user may create one immutable `confirmed` or `incorrect` feedback document, atomically paired with a +1 update to only the matching counter.
- `chat_room_listings`: authenticated discovery reads ordered by `created_at`; room, member, private-access, and message paths have separate membership/owner checks.
- `public_chat_messages`: authenticated reads ordered by `createdAt`, limited to 80; writes identify the sender.
- `chat_message_reports`: client create only; reports are not client-readable.
- `property_listings`: authenticated active reads; owners can read their own submissions, create strictly validated `pending_review` documents, update only photo URLs, and delete pending documents. Publishing remains trusted-admin/server only.
- `property_listings/{uid}/{listingId}/{photoIndex}` in Cloud Storage: owner uploads to a pending listing only; slots 0–4, image MIME types, and 5 MB maximum. Pending images are owner-only; active images require sign-in.
- `lost_pet_reports`: signed-in users can query active reports; report creation validates owner, location, last-seen time, phone sharing consent and field limits. Only the owner can resolve or delete a report.
- `community_places`: signed-in users can read submitted places; creation validates owner, category, coordinates and text bounds. Only the original owner can edit or delete.

## Adversarial Checks

- Unauthenticated property read: test that it is denied.
- Authenticated query containing active and pending listings: test that only active documents are returned.
- Active filtered rental query: test that the app query is allowed by the rules.
- Listing owner can submit a valid pending record and photo URLs; publishing, content edits, owner spoofing, and invalid values are denied by emulator tests.
- Listing documents must not contain phone numbers, email addresses, or other seller PII; seller contact workflows are outside this slice.
- Storage uploads require the matching pending listing owner, one of five fixed photo slots, an image MIME type, and a 5 MB maximum.
- Listing documents must not contain phone numbers, email addresses, or other seller PII; seller contact workflows are outside this read-only slice.
- Road report anonymous reads, counter-only writes, feedback-only writes, mismatched feedback/counter batches, spoofed vote paths, duplicate votes, and report-owner votes are denied by emulator tests; valid confirmation and incorrect-report batches succeed.
- Community place anonymous writes, owner spoofing, invalid coordinates, extra fields, and non-owner updates are denied by emulator tests; valid owner create/update and authenticated reads succeed.

Current emulator results: 30 Firestore and Storage tests passed. The suite covers community-place ownership/schema, road-report validation and atomic feedback, plus listing, room, profile, and Storage rules.
